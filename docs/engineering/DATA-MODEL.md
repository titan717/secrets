# Data model

Companion to [`schema.sql`](./schema.sql) (authoritative DDL). Status: proposed.

## 1. Core relationships

```
users ──< sessions
  │  └──< email_verification_tokens / password_reset_tokens
  ├──< conversation_members >── conversations ──< messages ──< reactions
  │                                │                  ├──< message_attachments >── attachments
  │                                │                  ├──< message_receipts
  │                                │                  └── reply_to_id (self)
  │                                └── dm_pairs (unique DM per user pair)
  ├──< dock_members >── docks ──< dock_channels ──< conversations(kind=channel)
  │                      ├──< dock_invites
  │                      └──< dock_audit_log
  ├──< notifications
  ├──< blocks (blocker/blocked)
  ├──< reports
  ├──< ai_conversations ──< ai_messages
  ├──< ai_provider_configs / ai_tool_permissions / ai_tool_approvals
  └──< call_participants >── call_rooms ── conversations
```

## 2. Key invariants

| Invariant | Enforcement |
| --- | --- |
| One message per `(sender, client_msg_id)` | unique index + `ON CONFLICT DO NOTHING` |
| `seq` is dense and gap-free per conversation | `UPDATE conversations SET last_seq = last_seq + 1 RETURNING` inside the insert transaction |
| One DM per user pair | `dm_pairs.pair_key` unique, created in the same transaction as the conversation |
| Exactly one of `body` / `ciphertext` | CHECK constraint (future E2EE swaps the column, not the API) |
| Channel belongs to a Dock | CHECK `kind='channel' ⇒ channel_id IS NOT NULL` |
| Username/email uniqueness is case-insensitive | unique index on `lower(...)` |
| No duplicate Dock channel names | unique partial index `WHERE deleted_at IS NULL` |
| Soft delete preserves replies and audit | `deleted_at` tombstones, body purged by retention job |

## 3. Authorization matrix (server-enforced)

Roles: `owner > admin > moderator > member > guest`. Channel access derives from Dock membership.

| Action | DM | Group | Dock channel | Who |
| --- | --- | --- | --- | --- |
| Read messages | member | member | dock member | `access(conv, user, 'read')` |
| Send message | member | member | dock member not muted/banned | `access(conv, user, 'write')` |
| Edit own message | author | author | author | author only |
| Delete any message | — | group admin | moderator+ | role check |
| Add/remove member | — | admin | admin | role check, cannot remove owner |
| Change roles | — | owner | owner/admin (≤ own role) | no privilege escalation |
| Create/rename/delete channel | — | — | admin | dock role |
| Revoke invite | — | — | admin | dock role |
| Create call token | member | member | dock member | calls service + API |
| Read AI context | member of that conversation only | same | same | explicit per-run consent |

Rules:
- A user can never grant a role above their own.
- Owner transfer is explicit and audited; the last owner cannot leave.
- `banned_at` blocks reads and writes; `muted_until` blocks writes only.
- Every mutation resolves the resource **through membership**, never by trusting an id from the client.

## 4. Deletion & retention

| Data | Delete behaviour | Retention |
| --- | --- | --- |
| Account | soft delete → sessions revoked, profile hidden, DMs disabled | purge 30 d |
| Message (for everyone) | tombstone, body nulled | 30 d |
| Message (for me) | `conversation_members.hidden_at` / per-user hide | immediate, private |
| Attachment | object deleted | 7 d after message delete |
| Dock | soft delete, channels hidden | purge 30 d |
| AI conversation | hard delete on request | immediate |
| Audit log | append-only | 180 d |
| Session | revoked rows kept for forensics | 30 d after expiry |

Data export: JSON bundle (profile, conversations, messages authored, Docks, AI chats) generated by a
background job, delivered as a short-lived signed URL.

## 5. Indexing rationale

| Query | Index |
| --- | --- |
| Message page (newest first) | `(conversation_id, seq DESC)` |
| Catch-up `sync since seq` | same index, range scan |
| Unread badge | `conversation_members.last_read_seq` (no count query) |
| Full-text search | GIN on `to_tsvector('simple', body)` |
| Discover Docks | partial index on `created_at` where public and live |
| Notification bell | partial index where `read_at IS NULL` |
| Pending AI approvals | partial index where `decision='pending'` |

## 6. Row-level security (defense in depth)

Application-level checks are mandatory. Optional RLS policies (enabled in production only) for the
highest-risk tables, using a per-request `SET LOCAL app.user_id`:

```sql
ALTER TABLE messages ENABLE ROW LEVEL SECURITY;
CREATE POLICY messages_read ON messages FOR SELECT USING (
  EXISTS (SELECT 1 FROM conversation_members m
          WHERE m.conversation_id = messages.conversation_id
            AND m.user_id = current_setting('app.user_id')::uuid)
);
```

Caveat: the API connects as a single role, so RLS is a second net, not the primary control. Tests must
cover the app-level checks independently.

## 7. Deviations from the recommended stack (deliberate)

| Recommendation | Choice | Why |
| --- | --- | --- |
| Drizzle/Prisma/Kysely | Hand-written SQL repositories | PGlite + no codegen toolchain on Android; explicit control of `ON CONFLICT` and partial indexes |
| Separate realtime service | Realtime module inside `apps/api` | Avoids duplicated auth/authorization over a network hop at MVP scale; extractable later |
| `attachments` on object storage | Adapter with `db` driver for dev | Zero-config local dev; production always `s3` |
| Argon2id | bcrypt (cost ≥ 11) or `@node-rs/argon2` if it installs | Native argon2 has no reliable android-arm64 prebuilt; bcrypt is explicitly allowed by the prompt |
